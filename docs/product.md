# 产品说明

## 从自身需求出发

最初要解决的是任务启动与坚持的问题，后来逐步加入成年人日程、生活片段、餐食记录和异地陪伴。典型使用者包括需要把安排转成行动的孩子、希望保持联系的家人，以及时间地点分散的家庭成员。这是基于自身场景的产品假设，不代表已经验证整个家庭市场。

## 三条完整流程

**安排 → 行动 → 看见积累。** 固定课程和新增任务进入家庭计划，“我的今天”集中展示当天安排，完成任务获得阳光，再用于收藏小岛装饰。固定课程按结束时间记录完成是应用规则，不是到课验证；奖励也不代表学习质量。

**近况 → 留言 → 家人回应。** 成员主动更新状态，写一句话或分享生活照片，家人在动态中查看和回应。部分状态按日程推导并标记来源，不涉及位置追踪，也不证明本人正在从事该活动。

**餐食输入 → AI 观察 → 本人确认。** 上传图片和文字，模型返回食物、搭配观察、信息不足与简单建议；本人决定是否分享。照片不能可靠确定精确热量和身体状况。

## 页面分工

| 页面 | 核心职责 |
| --- | --- |
| 家庭首页 | 下一步、家人状态、进入主要操作 |
| 我的今天 | 当天安排、任务、习惯和个人记录 |
| 家庭计划 | 固定课程、待排任务和时间调整 |
| 阳光收藏 | 积累反馈、收藏物件和三维场景 |
| 家人动态 | 近况、分享和回应 |

## 产品取舍

- 用共同的小岛呈现积累，让每位成员有参与空间，不引入成绩排名与惩罚。
- 任务与奖励使用明确规则，模型只进入适合图片理解与文字生成的环节。
- 原版满足小范围家庭使用；公开版增加演示空间隔离，避免陌生访客进入真实家庭记录。
- 暂时沿用文档同步和照片压缩，以保留已有实现；它有容量限制，不适合作为长期相册。
- 保留五页结构，改善配色、字体层级和小屏布局，减少原使用者重新学习的成本。

## 接下来验证什么

以下均是待验证的问题，不是已经取得的成果：

1. 下一步提示能否帮助启动任务？观察创建、安排、完成的过程，并结合访谈。
2. 家人是否愿意主动分享并收到回应？观察每周记录天数、回应比例和使用负担。
3. 新鲜感消退后，奖励是否仍有帮助？避免把积分上涨直接当作真实价值。
4. 餐食 AI 是否可靠？记录误识别、用户修改、放弃分享和失败恢复案例。
5. 多人使用是否稳定？验证并发写入、离线恢复、图片较多与额度耗尽。

作者提出实际需求、定义使用场景和功能，通过 AI 辅助实现、试用与迭代。代码和可复现操作体现需求拆解、交互设计、模型接入、数据持久化和多设备协作能力。历史使用由作者确认，与新环境测试分开记录；不将 AI 辅助开发包装为全部手写，也不将原型表述为已经商业验证的产品。
