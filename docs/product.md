# 做这个网页时，我在考虑什么

## 先解决家里的具体问题

我们家人分散在不同地方。我和妈妈平时上班，弟弟需要安排学习，但我们没办法一直在他身边。远程沟通时，既不容易看清他的日常安排，也容易把聊天变成催作业。

我希望他先学会把今天要做的事列出来、安排时间，完成后得到及时反馈。我们能看到安排、必要时协助调整和督促，而不是每次都重新问一遍。同时，这个地方也应该有我们自己的日常，不能只要求弟弟汇报。

## 为什么用网页

弟弟没有手机，主要用电脑；我和妈妈工作时也经常用电脑。网页符合现有设备条件，打开链接就能用，不需要专门安装应用。前端生成 HTML 页面供浏览器显示，交互由 React 实现；跨设备共享则需要后端和数据库，并不是上传一份 HTML 就能自动同步。

## 功能和需求怎样对应

| 家里的需要 | 我做的功能 | 仍然需要观察的地方 |
| --- | --- | --- |
| 弟弟不知道先做哪件事，时间安排不清楚 | 首页下一步、当天任务和课程、一周计划 | 他会不会主动用，而不是只等大人安排 |
| 完成作业后的反馈不够及时 | 完成任务获得阳光，用来收藏小岛装饰 | 新鲜感过后是否还愿意使用 |
| 我们不清楚他的安排和进度 | 共享日程、任务完成状态、家人状态 | 日程推导的状态不代表本人一定在做那件事 |
| 家人分散，日常沟通较少 | 文字、照片、生活动态和回应 | 是否真的增加交流，而不是多一项打卡负担 |
| 妈妈关注饮食，又不想逐项记录 | 餐食照片和补充说明、AI 搭配建议 | 模型能否正确识别；建议是否具体、好用 |

## 我保留的几条设计想法

- 用阳光和装饰给完成行为一个反馈，但不把积分当作学习效果。
- 让姐姐、妈妈也有自己的记录和分享，减少“只有弟弟被要求汇报”的感觉。
- 日程安排、打卡和奖励直接用程序规则处理；餐食识图才交给模型。
- AI 结果先展示给本人，再决定是否发到家庭动态。
- 这次整理作品时沿用原页面和操作，只调整视觉与细节，避免为展示另做一套自己不用的产品。

## 公开展示时做了什么调整

家里的真实资料替换为虚构任务、课程和动态。每个访客默认有独立空间，复制同岛链接才能进入同一份数据；演示中的角色切换不是正式的成员权限。

餐食 AI 保留接入代码、固定 prompt 和输出格式，但不开放我的付费模型额度。访客仍然可以直接记录和分享餐食。[这里说明 prompt 与密钥放在哪里](meal-ai.md)。

## 已做过和还没证明的事

我通过和 AI 讨论需求、生成代码、自己试用再修改，逐步把这个网页做出来。原版实际用过跨设备日程、动态同步和餐食分析；旧云资源释放后，这次重新建立演示环境，当前验收见 [验证记录](verification.md)。

这是从一个家庭的需要出发做的尝试。我没有做过大规模调研，也没有数据证明它提升了成绩、自驱力或家庭关系。更值得继续观察的是弟弟是否愿意自己安排任务、家人是否愿意持续回应，以及这个工具有没有减少反复沟通的负担。
